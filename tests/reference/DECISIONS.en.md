# Tracking how the original 49 pending decisions were settled

When the individual Reference acceptance cases were first written, 49 of them had the status `decision`: their expected meaning depended on syntax or policy that had not yet been settled. All 49 are now settled. This table maps each one to the current Reference section that defines it and to the form in which it is now verified.

Site-specific values are **not** pending syntax decisions. Operating time, admissible quality, device selection and gain are examples: they are arguments that the program or the installation contract states explicitly. This distinction follows [Reference §8.6](../../docs/reference/08-language-runtime-and-device-boundaries.md#86-언어-결정과-작성자가-정하는-정책).

How to read the table:

- **ID** — the acceptance case identifier. `REF-NN-…` belongs to Reference chapter `NN` (`00` is the [Language Reference](../../docs/LANGUAGE-REFERENCE.md) overview).
- **Settled decision summary** — the rule that resolved the former decision.
- **Reference** — the section that now owns the rule. Links point to the canonical Korean chapters.
- **Verification form** — the case status defined in the [acceptance test README](README.en.md):
  - `executable` (41 cases): a compiler acceptance/rejection case for settled syntax, run through the actual CLI.
  - `specified` (8 cases): a runtime, environment, Driver, UI or tool contract with written inputs, behavior and expected results. It counts as `externally-covered` only with an active external oracle link; otherwise it stays TODO. Neither outcome counts as a CLI execution pass.
