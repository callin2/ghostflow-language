# 固定版本导入的验证

依据：语言参考 §6.4–6.7。本文档跟踪实现进度与规划，并不取代语言规范。

**如何阅读本文档。** 第一节描述当前状态（2026-09-23）。后面各节是早期里程碑的日志，保留作历史记录。其中诸如“REF-06-010 仍为 RED”“lowerer 拒绝所有已解析的导入”或“没有公共 sourceClosure API”之类的陈述，在当时的里程碑中是成立的，现已被当前状态取代。

## 当前可执行切片（2026-09-23）

**状态。** REF-06-010 现在通过 CLI check 和产物构建。下文较早的“不支持路径”说明描述的是以前的里程碑。

**源闭包。** `compileSource` 接受显式的 `sourceClosure: [{ filename, revision, text }]`。

- 它使用浏览器安全的代码，以传递方式验证确切的摘要和修订版。
- 它不获取文件或网络资源。
- CLI 从文件系统收集这些规范文档。

**组合支持。** AST 组合支持：

- 标量输入/输出端口
- 参数
- state 和 let 表达式
- 嵌套实例
- 必需输入
- 精确的端口类型
- 单一写入者

组合环路和跨实例的下一状态反馈会被拒绝。文档和每个实例的源节点在产物映射中保持分离。

**产物恢复。** 恢复时会重新编译完整的闭包，并在接受产物之前比较字节码、manifest、追踪和来源。

**闭包上限。**

| 上限项 | 限制 |
| --- | --- |
| 文档 | 128 |
| 源总量 | 8 MiB |
| 实例 | 128 |
| 表达式变换访问次数 | 65,536 |

**测试。** `tests/composition-execution.test.mjs` 覆盖 Rust WASM 状态隔离、传递性的源解析、无效连接、缺失输入、参数错误、未使用输出的类型检查，以及产物/来源篡改。

**传感器与纯函数组合**已在 [#377](https://github.com/callin2/ghostflow-language/issues/377) 中加入。

- 根原始数据包扇出到彼此独立的每实例调理器。
- 公共传感器保留在 `manifest.sensors` 中。私有描述符位于 `manifest.sensorInstances`，带有 `sourceSensor`、`instance` 和 `port`。
- 载荷、可选性以及声明的采样间隔必须一致。
- 函数参数和 case 绑定保持词法作用域。
- 聚焦覆盖包括独立滤波、故障、恢复、陈旧、扫描回滚、私有数据包拒绝、源恢复，以及对实际调理后帧的 native/WASM 比较。
- GFB/ABI/帧协议保持不变。

**仍不支持：**

- timer/schedule/config/enum/resource/constraint 声明的组合
- 导入的意图链接展开
- 限定名的公共函数/类型导出

这些情况会明确失败，而不是悄无声息地丢失其实例语义。导入的修订版标签会与所提供闭包的身份标识进行核对；其真实性由调用方或目录负责。

## 已实现的解析器切片

*历史里程碑。*

`ControlParser` 接受顶层的固定版本导入头，并将其保存在单独的 `imports` AST 列表中。每个条目保留：

- 别名
- 相对 `.ghost.md` 定位符
- 修订版
- 摘要
- 源节点身份标识
- 每个固定字段的 token 位置

它在编写的 token 处报告以下错误：缺少修订版/摘要、无效的摘要语法、空的/latest 修订版、非规范/绝对/网络定位符，以及重复的别名。现有的文学式诊断重映射同样适用。

lowerer 在编译之前以如下消息拒绝所有已解析的导入：
`import execution requires a verified source closure and composition lowering,
which are not yet supported`。导入不能被悄无声息地忽略，包括未使用的导入。解析出非空的修订版字符串并不能证明解析器的修订版是不可变的。

TDD 证据：

- `build/import-header-red.log`：14 个测试，全部在旧的解析器边界处失败。
- `build/import-header-green.log`：272/272 个聚焦及受影响的语法测试通过，包括 `tests/import-header.test.mjs` 中全部 14 个新测试。
- 新测试套件已在 `tools/verify-language.mjs` 中显式注册。

在这个里程碑，REF-06-010 仍缺少被接受的组合。其验收预期以及所有其他 Reference 预期保持不变。

## 参数与组合语法切片

*历史里程碑。*

**参数。** `parameter` 默认值编译为有类型的不可变值，并记录在 `manifest.parameters` 中，独立于操作员设置。

- 前向参数引用的解析不依赖声明顺序。
- 循环默认值、类型不匹配，以及对 input、state 或可变 config 的依赖都会被拒绝。

**组合语法。** 解析器保留 `instance` 声明、具名特化参数以及 `connect` 端点，连同其原始源位置。局部组合验证会拒绝：

- 未知的导入别名/实例
- 重复的实例声明和参数
- 无效的根端口方向
- 相互竞争的供给者，包括同时由表达式和 `connect` 定义的根输出

**此里程碑的限制。** 在没有经过验证的源闭包时，公共编译器仍会拒绝有效的导入。它并不声称支持导入的参数名/类型、必需端口、精确的端口与传感器契约、实例隔离或可执行组合。

**证据。**

- REF-06-010 仍为 RED。
- REF-06-103 现在以实际的重复供给者诊断通过。
- `tests/import-composition.test.mjs` 有 21 个聚焦且通过的测试。
- 合并的 import/header/digest/control/compiler 运行 42/42 通过。

## 下一个最小实现边界

*历史计划。*

当时，与环境无关的 `tools/compile-source.mjs` 只接受一个规范文档，没有解析器/源闭包输入。`tools/ghostc.mjs` 只读取根文档。完整的下一个切片需要：

1. 一个显式的“所提供文档闭包”契约，携带每个规范文件名/定位符、不可变的修订版身份标识、原始文本以及经过验证的 UTF-8 摘要。浏览器和 Node 使用同一个验证器。验证器不得隐式获取文件或网络数据。
2. 可复用的导入头提取，而无需解析（当时尚不支持的）实例体。复用解析器的 token 规则，而不是正则扫描器。
3. 相对于导入方文档的相对定位符解析。解析只在所提供的闭包内进行；定位符的拼写不是源身份标识。
4. 针对缺失依赖、修订版不一致、摘要不匹配、定位符绑定歧义以及传递性导入环的诊断，每个诊断都保留导入方的源范围。验证传递依赖，而不仅仅是根导入。在验证结果中保留原始的完整正文和身份标识。
5. 公共编译器集成：验证闭包，但在组合降级/来源实现之前仍拒绝实例执行。CLI 的文件系统收集是接入同一契约的独立适配器。

**必需的测试。** 将一个有效的两级固定版本闭包与每种单独的损坏情况配对。同时覆盖菱形复用、在不同定义中复用别名、路径规范化、环路以及字节/文档资源边界。验证不得修改所提供的闭包。

当时输入契约仍是主集成者的设计决策；解析器切片没有添加任何推测性的公共解析器 API。

此后，REF-06-010 还需要 instance/parameter/connect 解析、每实例状态隔离、精确的端口/质量检查、依赖排序、传递性的下一状态限制、单一写入者，以及源/修订版来源。将源文本扁平化并丢弃原始文档身份标识不是可接受的捷径。

## CLI 直接摘要预检

*历史里程碑。*

这个小切片位于 `tools/ghostc.mjs` 中。在解析尚不支持的实例体之前，CLI 会：

1. 复用 `parseControlImports` 检查导入头；
2. 将每个直接相对定位符相对于导入方的根文件名进行解析；
3. 将固定的 SHA-256 与原始文件字节进行比较。

导入的正文、UTF-8 编码和 CRLF 字节原样参与比较。无效的 UTF-8、超大文档、无法读取的文件以及摘要不匹配，都会在发布产物之前于编写的 import token 处被拒绝。

在这个里程碑，它仅是直接的文件系统完整性验证：没有公共 sourceClosure API、递归解析器、修订版真实性证明或被接受的组合。匹配的依赖仍会进入现有的不支持编译器路径。浏览器编译不会通过这个 CLI 辅助工具获取文件。

**证据。** `tests/import-cli-digest.test.mjs` 以 check 和 build 两种模式运行未修改的 REF-06-102 测试夹具。它覆盖精确的 UTF-8/CRLF 匹配、导入正文篡改、保留已有产物、缺失文件以及无效 UTF-8。

- `build/import-cli-digest-red.log` 记录了四个失败和一个原本就通过的不支持路径对照。
- `build/import-cli-digest-green2.log` 记录了 156/156 个测试通过，包括全部五个新用例、导入解析器覆盖以及现有的完整 CLI 语法诊断套件。
- 没有任何 Reference 预期发生变化。
