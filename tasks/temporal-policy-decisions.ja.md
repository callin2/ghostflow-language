# 時間的ポリシーの決定

**ステータス: 承認済みのプロダクト決定であり、Reference §§3.5 と 4.4 に記録されています。**

このファイルは、テストと技術契約のための計画記録として残しています。コンパイラやランタイムのサポートを主張するものではありません。

**このドキュメントの内容:**

| トピック | 一行での決定 | Reference |
| --- | --- | --- |
| `true_for` | Driver が認証した連続区間だけを数えます。補間はしません。 | §4.4 |
| `after_event` | 各開始イベントが、それぞれ独立した結果を保持します。 | §4.4 |
| スケジュールの複数回の通過 | 通過したすべての発生（オカレンス）を取りこぼし（missed）とし、どれも実行しません。 | §3.5 |

以下の各決定では、Reference に適用された韓国語の文を引用しています。

## 確定した決定

### `true_for`

`true_for(..., quality: measured)` が累積できるのは、インストールされた Driver が実際に観測されたと認証した連続区間だけです。離れた点サンプルは、その間の区間を認証しません。

コンパイラ/ランタイムは次のことをしてはなりません。

- サンプル間を補間すること
- 期待される周期、スキャン周期、重複サンプル、クロックのみの tick を、観測された連続性として扱うこと

Reference §4.4 の既存の `true_for` の文の後に適用されたもの:

> 연속성은 Driver가 실제 관측되었다고 인증한 interval만 이어 붙인다. 서로 떨어진
> sample 사이를 보간하거나 expected cadence, scan cadence, duplicate, clock-only tick을
> 관측 증거로 간주하지 않는다.

### `after_event`

それぞれの異なる開始イベントは、独立して追跡される結果を持ちます。

- 重なり合うイベントも区別可能なままです。
- 後の開始イベントが、以前の保留中または完了済みの結果を上書きすることはありません。
- 既存の半開区間 `[e,e+window)` は、引き続き各イベントの同一性に適用されます。

Reference §4.4 の既存の `after_event` の文の後に適用されたもの:

> 겹치는 event도 identity별 result를 독립적으로 유지한다. 새 start event는 이전
> pending 또는 completed result를 덮어쓰지 않는다.

これにより、以前 `tasks/after-event-design.md` で保留とされていたプロダクト上の選択が解決されます。イベントごとに独立した結果を選択します。

### スケジュールの複数回の通過

受け入れられた 1 つの観測区間が、同じスケジュールの 2 つ以上の発生を通過した場合、通過したすべての発生を取りこぼしとして記録し、そのいずれも実行しません。

この規則が適用されるのは、複数回の通過のケースだけです。ちょうど 1 つの発生を通過したスキャンは、引き続き通常の pulse の受け入れ（アドミッション）規則を使います。

Reference §3.5 の観測ギャップと復旧の項に適用されたもの:

> 하나의 accepted observation interval에서 같은 schedule의 occurrence를 둘 이상
> 교차하면 교차한 occurrence를 모두 missed로 기록하고 어느 것도 실행하지 않는다.
> 정확히 하나만 교차한 경우에는 ordinary admission 규칙을 그대로 적용한다.

## 決定的な仕様シナリオ

各シナリオは、承認された振る舞いを、もっともらしいが誤った振る舞いから切り分けます。

1. **認証された連続性:** Driver が認証した 2 つの true の区間が接しており、その和集合が正の継続時間に達する場合、境界で `true_for` が true になります。
2. **補間なし:** `t=0` と `t=d` に true の点サンプルがあっても、その間に認証された区間がなければ、期待される周期や実際のスキャン周期にかかわらず `true_for` は満たされません。
3. **連続性の途切れ:** 認証されたカバレッジのギャップ、false の区間、または受け入れられない品質は、累積された true の区間をリセットします。
4. **重なり合うイベント:** イベント `A` が開始し、`A` の window が終わる前にイベント `B` が開始します。述語の観測は、個別に参照可能な `A` と `B` の結果をそれぞれ更新します。`B` が `A` を置き換えることは決してありません。
5. **半開のイベント境界:** ちょうど `e + window` にある証拠は、そのイベントの結果からだけ除外され、重なり合う別の結果を消すことはできません。
6. **Solar の複数回の通過:** `gap = skip_after(3days)` のとき、2 つの Solar の発生を含む受け入れられた区間は、両方を取りこぼしとして記録し、どちらも実行せず、確定後に同一のリトライを行っても 2 つのレコードが重複することはありません。
7. **単一通過の対照:** 同じスケジュールで通過した発生が 1 つの場合は、通常の述語/受け入れの振る舞いに従います。これにより、新しい取りこぼしポリシーが広く適用されたわけではないことが証明されます。

## まだ必要な技術契約

これらの決定は、次の実装契約を選択するもの**ではありません**。

- Driver の区間証明書のワイヤ形式、信頼のバインディング、カバレッジの検証、クロック/エポックの同一性、変換された信号を通じた証明の伝播。
- 認証された区間に対する、有界な状態、チェックポイント、リプレイ、リソースの計上。
- イベント入力の ABI、不透明な同一性のバインディング、個別に参照可能な結果の射影、結果の保持、重なりの容量、遅延、否定/保留の結果の形、イベントの故障/品質の振る舞い。
- スケジュールの複数回の通過に対する、型付きの取りこぼし理由とトレース表現、プロバイダの事実の完全な上限、発生台帳（レジャー）の容量、リプレイのエンコーディング、修正の扱い。
- 具体的なバイトレイアウト、ABI、ストレージ予算、オーバーフロー規則、展開時のプロバイダのケイパビリティのいずれも。
