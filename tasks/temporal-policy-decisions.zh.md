# 时间策略决策

**状态：已批准的产品决策，已记录在 Reference §§3.5 和 4.4 中。**

本文件仍作为测试和技术契约的规划记录。它并不声称编译器或运行时已提供支持。

**本文内容：**

| 主题 | 一句话决策 | Reference |
| --- | --- | --- |
| `true_for` | 只计入经 Driver 认证的连续区间；不做插值。 | §4.4 |
| `after_event` | 每个起始事件各自保留独立的结果。 | §4.4 |
| 多重调度计划交叉 | 所有被交叉的触发实例都记为错过；一个都不执行。 | §3.5 |

下面的每项决策都引用了已写入 Reference 的韩文原句。

## 已确定的决策

### `true_for`

`true_for(..., quality: measured)` 只能累积已安装 Driver 认证为实际观测到的连续区间。彼此分离的点样本并不能认证它们之间的区间。

编译器/运行时不得：

- 在样本之间插值；或
- 将预期节拍、扫描节拍、重复样本或仅含时钟的 tick 视为已观测到的连续性。

已写入 Reference §4.4、位于现有 `true_for` 句子之后：

> 연속성은 Driver가 실제 관측되었다고 인증한 interval만 이어 붙인다. 서로 떨어진
> sample 사이를 보간하거나 expected cadence, scan cadence, duplicate, clock-only tick을
> 관측 증거로 간주하지 않는다.

（中文释义：连续性只拼接 Driver 认证为实际观测到的区间。不在彼此分离的样本之间插值，也不将预期节拍、扫描节拍、重复样本或仅含时钟的 tick 视为观测证据。）

### `after_event`

每个不同的起始事件都有一个独立跟踪的结果。

- 重叠的事件仍可相互区分。
- 后来的起始事件不会覆盖较早的待定（pending）或已完成（completed）结果。
- 现有的半开区间 `[e,e+window)` 继续适用于每个事件身份标识。

已写入 Reference §4.4、位于现有 `after_event` 句子之后：

> 겹치는 event도 identity별 result를 독립적으로 유지한다. 새 start event는 이전
> pending 또는 completed result를 덮어쓰지 않는다.

（中文释义：重叠的事件也按身份标识独立保持各自的结果。新的起始事件不会覆盖之前的待定或已完成结果。）

这解决了 `tasks/after-event-design.md` 中此前标记为待定的产品选择：选择按事件独立的结果。

### 多重调度计划交叉

当一个被接受的观测区间交叉了同一调度计划的两个或更多触发实例（occurrence）时，将每个被交叉的触发实例记录为错过（missed），且一个都不执行。

此规则只适用于多重交叉的情形。恰好交叉一个触发实例的扫描仍使用普通的 pulse 准入规则。

已写入 Reference §3.5 的观测间隙与恢复部分：

> 하나의 accepted observation interval에서 같은 schedule의 occurrence를 둘 이상
> 교차하면 교차한 occurrence를 모두 missed로 기록하고 어느 것도 실행하지 않는다.
> 정확히 하나만 교차한 경우에는 ordinary admission 규칙을 그대로 적용한다.

（中文释义：如果在一个被接受的观测区间中交叉了同一调度计划的两个或更多触发实例，则将被交叉的触发实例全部记录为 missed，且一个都不执行。恰好只交叉一个时，照常适用普通准入规则。）

## 决定性的规范场景

每个场景都将已批准的行为与一个看似合理的错误行为区分开来。

1. **经认证的连续性：**两个相接的、经 Driver 认证的 true 区间，其并集达到正的持续时间时，`true_for` 在边界处为 true。
2. **不插值：**在 `t=0` 和 `t=d` 处为 true 的点样本，若它们之间没有经认证的区间，则不满足 `true_for`，无论预期或实际的扫描节拍如何。
3. **连续性中断：**认证覆盖中的间隙、false 区间或不可接受的质量，会重置累积的 true 区间。
4. **重叠的事件：**事件 `A` 开始，然后事件 `B` 在 `A` 的 window 结束之前开始。谓词观测分别更新可单独寻址的 `A` 和 `B` 结果；`B` 绝不会替代 `A`。
5. **半开的事件边界：**恰好位于 `e + window` 的证据只从该事件的结果中排除，不能抹去另一个重叠的结果。
6. **多重 Solar 交叉：**在 `gap = skip_after(3days)` 下，一个包含两个 Solar 触发实例的被接受区间会将两者都记录为错过，两者都不产生执行，并且提交之后相同的重试不能重复这两条记录。
7. **单次交叉对照：**同一调度计划只交叉一个触发实例时，遵循普通的谓词/准入行为。这证明新的错过策略没有被宽泛地套用。

## 仍需的技术契约

这些决策**并未**选定以下实现契约：

- Driver 区间证书的线格式结构、信任绑定、覆盖校验、时钟/纪元身份标识，以及证明在变换后信号中的传播。
- 经认证区间的有界状态、检查点、重放和资源用量核算。
- 事件 input ABI、不透明身份标识绑定、可独立寻址的结果投影、结果保留、重叠容量、延迟、否定/待定结果的结构，以及事件故障/质量行为。
- 多重调度计划交叉的带类型错过原因和 trace 表示、完整的 provider 事实边界、触发实例账本容量、重放编码以及修正处理。
- 任何具体的字节布局、ABI、存储预算、溢出规则或部署时的 provider 能力。
