# Issue 135：最初の実行可能なスケジュールスライス

トラッカー：https://github.com/callin2/ghostflow-language/issues/135

この日付付きの実装セッションは `REF-03-024`（`Daily`）のみを対象とします。

- 変更されていない正本の文芸的（literate）フィクスチャは、実行可能な control 成果物にコンパイルされ、既存の Rust VM の経路で実行されなければなりません。
- ホストアダプタは、有界で完全な発生（オカレンス）事実の集合を供給してもかまいません。
- 述語の評価、クロック/受け入れ（アドミッション）状態、射影、トランザクションの確定、意図については、引き続き Rust が責任を負います。

## テストを先に

1. 正確なフィクスチャが、ディスクリプタ成果物のゲートで現在失敗していることを記録する。
2. 起動時ベースラインと 1 回の Daily の交差を伴う、対象を絞った実行可能 Reference のオラクルを追加する。フィクスチャのソースと、期待される言語契約は変更しない。
3. 既存のスケジュールランタイムのハーネスがサポートする、最小限のネイティブ/WASM パリティ（一致性）チェックを追加する。

## 実装の境界

- `schedule_clock` と、有界のスケジュール受け入れ/ランタイムの仕組みを再利用する。
- アーキテクチャレビューで、独立した GFB8/tag-3 の Daily ディスクリプタと control-v7 マニフェストが承認されました。
  - GFB7 は PID 専用のままです。
  - GFSF v2 は、明示的なトリガー種別と常用時の fold を運びます。
  - 現在の Solar の利用側は GFSF v1 のままです。
- IANA の発生生成とコンテキストのリビジョンは、プロバイダ/アダプタの境界に置く。JavaScript の式、状態、受け入れ、意図の VM を追加しない。
- Unknown の理由、起動/復旧ベースライン、ギャップの終端化、ロールバック、発生の同一性、DST ポリシーのフィールド、正確なソースの同一性を保持する。
- このスライスでは、DailySlots、Periodic、Cron、TimeSlots、WorkCalendar、Tide の振る舞いを変更しない。

## ファイルの担当

- issue-135 のワーカーは、この計画、対象を絞ったスケジュール/コンパイラ/ランタイムのファイル、`REF-03-024` 向けの対象を絞ったテストを担当します。
- `tasks/plan.md` や、時間系ワーカーのケースは編集しません。
- 共有の `tests/reference/cases/02-time-control.json` フィクスチャは、正当な実行可能入力コンテキストが必要な場合を除き、読み取り専用です。そのソースと期待値は変更しません。

## 受け入れ

- 変更前の対象を絞ったテストが、既知のディスクリプタのみという理由で RED になる。
- 変更されていない `REF-03-024` のソースが、実行可能な成果物を生成する。
- `ghostsim` が、Rust を通じてベースラインと 1 回の受理された Daily の交差を実行する。
- 対象のテストが合格し、変更はローカルにコミットされる。push、マージ、USB、ハードウェアの作業は行わない。
