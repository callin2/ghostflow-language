# オーサリングベースラインの来歴

この記録は、オーサリング効率テストが通常の Rust コアの編集で壊れていた理由と、それを置き換えた恒久的な契約について説明します。ここでの「来歴（provenance）」とは、ベンチマークが測定された対象であるソースファイル（ツール、ロックファイル、Reference、Rust コア）の同一性を指します。

## 障害

オーサリング効率テストは、2種類の異なる記録を混在させていました。

1. レビュー済みで日付の付いたベンチマークの測定値
2. 現在チェックアウトされているコンパイラと Rust コアから計算したハッシュ

そのうえでテストは、ライブレポート全体が履歴の JSON と等しいことを要求していました。さらに、ライブの集約ハッシュをテストコード内に固定していました。その結果、コンパイル、修正、診断、検索の上限、シミュレーション結果、トークン測定値がすべて変わらない場合でも、正当な Rust コアの編集はすべて CI を失敗させました。古いハッシュを新しいものに置き換えれば一度は CI が通りましたが、欠陥のある契約はそのまま残っていました。

## 恒久的な契約

この修正は、凍結された履歴スナップショットとライブの来歴を分離します。

| 記録 | 出所 | 比較方法 |
| --- | --- | --- |
| 日付付き JSON 内の履歴上のソース同一性 | `c7233b1` でレビュー済み | 保存されたダイジェストを再現し、独立に固定されたダイジェストと一致しなければならない |
| ライブの来歴 | 実行のたびにチェックアウトされたファイルから導出 | 報告のみ。スナップショットと等しい必要はない |
| ベンチマークの証拠（`sourceRevision` 以外のすべて） | 日付付き JSON | 完全一致で比較 |

規則の詳細：

- 従来の日付付き JSON は、`c7233b1` からレビュー済みのソース同一性を保持しています。その集約ダイジェストは
  `45f4efc0e2a8c7d227d04622ed4dc61ee63430646fd0751dd4e332fd35f5323f` です。
- 保存されたソース同一性は、保存されたダイジェストを再現しなければなりません。また、独立に固定されたそのレビュー済みダイジェストとも一致しなければなりません。同一性のフィールドを編集してから保存ダイジェストを再計算することは拒否されます。
- 各テスト実行では、現在のツール、ロックファイル、シナリオランナー、Reference、Rust コアの同一性を、チェックアウトされたファイルから導出します。このライブの来歴は報告されますが、履歴スナップショットと等しいことは要求されません。
- `sourceRevision` 以外のすべてのベンチマーク証拠は、引き続き完全一致で比較されます。対象は、ケース、ソース同一性、セクションのダイジェストとバイト数の上限、診断、修正とシミュレーションのラウンド、安全な仮想意図、合計、トークンデータです。
- 意図的な新しいベンチマークは、新しい日付付きの成果物です。日常的なソース作業が、既存の履歴ベンチマークを書き換えることは決してありません。

焦点を絞った回帰テストは、実際の一時ソースツリーを使用します。このテストは次のことを行います。

- 期待されるツリーと集約ダイジェストを固定します。
- コアの同一性または Reference 全体の同一性を変更すると、ベンチマークを変えずにライブの来歴が変わることを証明します。
- 宣言されたファイルの欠落を拒否します。
- ダイジェストが再計算されていても、保存された同一性の改ざんを拒否します。
- 変更されたベンチマーク測定値を拒否します。

ベンチマークが参照したすべての Reference セクションの正確なダイジェストとバイト数は、引き続き比較の対象です。
