# 저작 기준선 출처 정보

## 실패

저작 효율성 테스트가 서로 다른 두 기록을 하나로 합쳤습니다.

1. 검토된 날짜 지정 벤치마크의 측정값
2. 현재 체크아웃된 컴파일러와 Rust 코어에서 산출한 해시

그 결과 전체 실시간 보고서가 과거 JSON과 같아야 했고, 테스트 코드에는 실시간 집계 해시가 고정되었습니다. 따라서 정당한 Rust 코어 수정은 컴파일, 수정, 진단, 검색 한도, 시뮬레이션 결과, 토큰 측정값이 모두 그대로여도 CI를 실패하게 만들었습니다. 기존 해시를 새 값으로 바꾸면 CI는 한 번 통과하지만 잘못된 계약은 유지됩니다.

## 영구 계약

- 기존 날짜 지정 JSON은 `c7233b1`에서 검토된 소스 식별 정보를 유지하며, 집계 다이제스트는
  `45f4efc0e2a8c7d227d04622ed4dc61ee63430646fd0751dd4e332fd35f5323f`입니다.
- 저장된 소스 식별 정보는 저장된 다이제스트와 일치해야 하며, 독립적으로 고정한 검토 다이제스트와도 일치해야 합니다. 식별 필드를 고친 뒤 저장 다이제스트를 다시 계산해도 거부됩니다.
- 각 테스트 실행은 체크아웃된 파일에서 현재 도구, 잠금 파일, 시나리오 러너, 참조 문서, Rust 코어의 식별 정보를 산출합니다. 해당 실시간 출처 정보는 보고되지만 과거 스냅샷과 같을 필요는 없습니다.
- `sourceRevision` 외의 모든 벤치마크 증거는 정확히 비교합니다. 여기에는 사례, 소스 식별 정보, 절 다이제스트와 바이트 한도, 진단, 수정 및 시뮬레이션 라운드, 안전한 가상 의도, 합계와 토큰 데이터가 포함됩니다.
- 의도적으로 새 벤치마크를 만들 때는 새 날짜의 아티팩트로 기록합니다. 일반 소스 작업은 기존 과거 벤치마크를 다시 쓰지 않습니다.

집중 회귀 테스트는 실제 임시 소스 트리를 사용합니다. 예상 트리 및 집계 다이제스트를 고정하고, 코어와 참조 문서 전체의 식별 정보 변경이 벤치마크는 바꾸지 않고 실시간 출처 정보만 바꾸는지 입증합니다. 선언된 파일 누락, 다이제스트를 다시 계산한 저장 식별 정보 변조, 변경된 벤치마크 측정값도 거부합니다. 벤치마크가 참조한 각 참조 문서 절의 정확한 다이제스트와 바이트 수는 비교에 계속 포함됩니다.
