# 저작 기준선 provenance(출처)

이 기록은 저작 효율성 테스트가 평범한 Rust 코어 수정에도 실패했던 이유와, 이를 대체한
영구 계약을 설명합니다. 여기서 "provenance"는 벤치마크를 측정할 때 기준이 된 소스 파일
(도구, 잠금 파일, Reference, Rust 코어)의 식별 정보를 뜻합니다.

## 실패

저작 효율성 테스트는 성격이 다른 두 기록을 섞어 사용했습니다.

1. 검토를 거친 날짜 지정 벤치마크의 측정값
2. 현재 체크아웃된 컴파일러와 Rust 코어에서 계산한 해시

그런 다음 테스트는 실시간 보고서 전체가 과거 JSON과 같기를 요구했습니다. 또한 테스트
코드에 실시간 집계 해시를 고정했습니다. 그 결과 정당한 Rust 코어 수정은 모두 CI 실패로
이어졌습니다. 컴파일, 수정, 진단, 검색 한도, 시뮬레이션 결과, 토큰 측정값이 하나도 바뀌지
않은 경우에도 마찬가지였습니다. 기존 해시를 새 해시로 바꾸면 CI는 한 번 통과하지만,
잘못된 계약은 그대로 남습니다.

## 영구 계약

해결책은 고정된 과거 스냅샷과 실시간 provenance를 분리하는 것입니다.

| 기록 | 출처 | 비교 방식 |
| --- | --- | --- |
| 날짜 지정 JSON의 과거 소스 식별 정보 | `c7233b1`에서 검토됨 | 저장된 다이제스트를 재현해야 하며, 독립적으로 고정한 다이제스트와도 일치해야 함 |
| 실시간 provenance | 실행할 때마다 체크아웃된 파일에서 도출 | 보고만 함. 스냅샷과 같을 필요 없음 |
| 벤치마크 증거(`sourceRevision` 외 전부) | 날짜 지정 JSON | 정확히 비교 |

세부 규칙은 다음과 같습니다.

- 기존 날짜 지정 JSON은 `c7233b1`에서 검토된 소스 식별 정보를 유지합니다. 그 집계
  다이제스트는
  `45f4efc0e2a8c7d227d04622ed4dc61ee63430646fd0751dd4e332fd35f5323f`입니다.
- 저장된 소스 식별 정보는 저장된 다이제스트를 재현해야 합니다. 또한 독립적으로 고정한 검토
  다이제스트와도 일치해야 합니다. 식별 필드를 고친 뒤 저장된 다이제스트를 다시 계산하는
  방식은 거부됩니다.
- 각 테스트 실행은 체크아웃된 파일에서 현재 도구, 잠금 파일, 시나리오 러너, Reference,
  Rust 코어의 식별 정보를 도출합니다. 이 실시간 provenance는 보고되지만, 과거 스냅샷과
  같을 필요는 없습니다.
- `sourceRevision` 밖의 모든 벤치마크 증거는 여전히 정확히 비교합니다. 여기에는 사례, 소스
  식별 정보, 절 다이제스트와 바이트 한도, 진단, 수정 및 시뮬레이션 라운드, 안전한 가상
  의도, 합계, 토큰 데이터가 포함됩니다.
- 의도적으로 만든 새 벤치마크는 새 날짜 지정 아티팩트입니다. 일상적인 소스 작업은 기존
  과거 벤치마크를 절대 다시 쓰지 않습니다.

집중 회귀 테스트는 실제 임시 소스 트리를 사용합니다. 이 테스트는 다음을 수행합니다.

- 예상 트리 다이제스트와 집계 다이제스트를 고정합니다.
- 코어 식별 정보나 Reference 전체 식별 정보를 바꾸면 벤치마크는 바뀌지 않고 실시간
  provenance만 바뀐다는 것을 입증합니다.
- 선언된 파일이 없으면 거부합니다.
- 저장된 식별 정보의 변조를, 다이제스트를 다시 계산한 경우에도 거부합니다.
- 바뀐 벤치마크 측정값을 거부합니다.

벤치마크가 참조한 모든 Reference 절의 정확한 다이제스트와 바이트 수는 계속 비교 대상에
포함됩니다.
