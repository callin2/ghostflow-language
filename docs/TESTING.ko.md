# GhostFlow 적합성 및 신뢰성 테스트

상태: 규범적 테스트 정책. 현재 제품군의 통과는 해당 실행에 명시된 요구 사항과 설정에 대한 증거일 뿐입니다. 언어 전체 또는 물리 Farm Device가 검증되었다는 뜻은 아닙니다.

## SQLite에서 얻은 원칙

GhostFlow는 소규모 이식 가능 제어 언어에 맞는 SQLite 테스트 규율의 일부를 채택합니다.

1. 테스트 가능한 모든 규범 문장은 요구 사항입니다. 안정적인 내용 기반 ID, 정확한 소스 위치, 실행 가능한 테스트 또는 명시적인 대기 사유가 있어야 합니다.
2. 공개 인터페이스와 배포되는 바이트를 테스트하세요. 파서 전용 또는 소스 수준 테스트만으로 GFB, 네이티브 런타임, WASM 동작을 입증할 수 없습니다.
3. 서로 독립된 하네스를 유지하세요. 컴파일러 테스트, GFB 로더/검증기 테스트, 네이티브 실행, WASM 실행, 호스트 수명 주기 테스트는 서로 다른 결과를 낼 수 있어야 합니다.
4. 모든 경계의 양쪽과 모든 불리언 결정을 시험하세요. 선언된 한도에는 최소, 최대, 바로 안쪽, 바로 바깥쪽 사례가 필요합니다.
5. 각 원자적 경계에서 실패를 주입하고 매번 불변 조건을 확인하세요. 컴파일, 로드, 틱, 리셋, 핫스왑, 지속성 작업이 거부될 때 일부 상태나 출력만 조용히 커밋되어서는 안 됩니다.
6. 잘못되었거나 변조된 아티팩트는 일반적인 악성 입력으로 다루세요. 로더는 패닉 없이 거부하거나 별도로 유효한 모듈로 받아들여야 합니다. 변조본이 원본과 동등하다고 가정하지 마세요.
7. 동일한 아티팩트와 입력 추적으로 독립 구현 또는 대상을 비교하세요. 네이티브와 WASM의 일치는 필수입니다. 두 대상이 같은 코어 의미를 공유하는 경우에는 별도 오라클도 필요합니다.
8. 테스트 자체를 측정하세요. 재현 가능한 명령과 정당한 제외 항목을 체크인한 뒤 분기/조건 커버리지와 변이 테스트를 릴리스 게이트로 삼습니다. 테스트 개수로 백분율을 추정하지 않습니다.
9. 수정한 모든 결함에는 수정 수용 전에 최소한의 영구 회귀 사례를 추가합니다.
10. 소비자가 배포하는 것과 동일한 기능 설정 및 릴리스 모드 아티팩트로 릴리스 제품군을 실행합니다.

이 정책은 요구 사항 카탈로그, 배포 상태 테스트 TH3, 경계 및 오류 주입 반복, 독립 SQL Logic Test 비교, 분기/MC/DC 커버리지, 변이 테스트에 관한 SQLite의 공개 설명에서 영감을 받았습니다. GhostFlow가 SQLite의 커버리지나 보증 수준에 도달했다고 주장하지 않습니다.

## 요구 사항 기록

`contracts/requirements/` 아래의 기계 검사 카탈로그는 다음을 기록합니다.

- 정규화된 규범 문장에서 산출한 안정 ID
- 정확한 규범 문장과 문서 위치
- 담당 계층과 지원 대상
- 해당 문장을 검증하는 테스트 ID 또는 비어 있지 않은 대기 사유
- 검증됨, 일부 검증됨, 작업 대기 중을 구분하는 상태

규범 문장을 바꾸면 새 ID를 만듭니다. 이전 테스트가 입증한 내용을 조용히 바꾸지 말고 이전 기록을 대체 이력으로 유지합니다.

## 검증 계층

| 계층 | 최소 증거 |
|---|---|
| 문법 | 정확한 진단을 포함한 허용 및 거부 토큰/AST 사례 |
| 형식 및 하향 변환 | 형식화된 소스에서 검사 가능한 GFB 구조 및 매니페스트로 변환 |
| GFB 검증기 | 유효, 잘림, 한도 초과, 변조된 바이트 시퀀스 |
| 네이티브 VM | 정확한 상태, 요청 의도, 안전 의도, 오류, 원자성 추적 |
| WASM VM | 네이티브와 같은 아티팩트/추적 및 오류 분류 |
| 호스트 수명 주기 | 설치, 활성화, 첫 스캔, 실패 스캔, 리셋, 핫스왑, 재생 |
| 제품 어댑터 | 식별된 언어 아티팩트만 사용. 별도 평가기 금지 |
| Device | 별도 빌드, 보드/프로파일, 드라이버, 물리 관찰 게이트 |

## 출력 안전 규칙

출력 선언은 논리적 의도 포트의 이름과 형식을 지정합니다. 상태를 유지하거나 물리 릴레이의 시작/실패 안전 레벨을 설정하지 않습니다. 선언된 출력마다 스캔별 연결 표현식이 정확히 하나 있어야 합니다. 상수 의도는 상수 연결 표현식으로 작성합니다.

첫 성공 스캔 전에는 VM 출력 의도가 없습니다. 호스트/드라이버는 설정된 안전 상태를 유지해야 하며 Farm Device의 기본 정책은 OFF입니다. 컴파일, 로드, 활성화, 틱 실패가 소스 문법만으로 의도를 만들어내지 못합니다. 물리 시작, 감시 타이머, 실패 안전 정책은 식별된 호스트 바인딩의 책임이며 이식 가능한 VM 프로그램과 별도로 다룹니다.
