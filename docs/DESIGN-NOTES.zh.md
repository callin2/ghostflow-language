# 语言设计说明

本页概述 GhostFlow 设计背后的语言层面考量。

**所选的表层形式。** 一个 GhostFlow 程序是一个具名的 `control`。它包含：

- 带类型的声明；
- 显式的下一状态方程；
- 输出意图连接。

文学式（literate）源把说明文字放在代码旁边，而可执行语义和映射后的诊断保持不变。编译器与可移植运行时一同进行版本管理。因此，同一个程序可以先通过原生追踪和 WASM 追踪进行检查，再由兼容的设备宿主使用。

**可复现的执行。** 以下四项性质使执行可复现：

- 显式的状态边界；
- 有界的表达式开销；
- 受约束的副作用；
- 显式的宿主输入。

可选传感器或安装元数据不得在不知不觉中引入对物理设备的假设。共享站点的约束是带有显式绑定的可执行源契约或 profile 契约。

**延伸阅读。** 详细的[语言契约](LANGUAGE.zh.md)、[控制表层](LANGUAGE-SURFACE.zh.md)、[文学式规则](LITERATE.zh.md)和[约束](CONSTRAINTS.zh.md)文档将已选定的语法与设计提案区分开来。[实现边界](IMPLEMENTATION.zh.md)描述了所保留的可执行子集。
