# 编写基线的来源（provenance）

本记录说明为什么编写效率测试会在普通的 Rust 核心修改上失败，以及取而代之的永久契约。这里的“来源”（provenance）指的是基准测试所依据的源文件（工具、锁文件、Reference、Rust 核心）的身份标识。

## 故障

编写效率测试混用了两种不同的记录：

1. 来自一次经过评审、带日期的基准测试的测量结果；以及
2. 根据当前检出的编译器和 Rust 核心计算出的哈希。

随后，测试要求整个实时报告与历史 JSON 完全相等。它还在测试代码中固定了实时的汇总哈希。结果是，任何正当的 Rust 核心修改都会导致 CI 失败，即使每一次编译、修正、诊断、检索边界、仿真结果和 token 测量都保持不变。用新哈希替换旧哈希能让 CI 通过一次，但错误的契约依然存在。

## 永久契约

修复方案把冻结的历史快照与实时来源分开：

| 记录 | 来源 | 比较方式 |
| --- | --- | --- |
| 带日期 JSON 中的历史源身份标识 | 在 `c7233b1` 经过评审 | 必须能复现其存储的摘要，并与一个独立固定的摘要一致 |
| 实时来源 | 每次运行时从检出的文件派生 | 仅作报告；不必与快照相等 |
| 基准证据（`sourceRevision` 之外的全部内容） | 带日期的 JSON | 精确比较 |

详细规则：

- 遗留的带日期 JSON 保留来自 `c7233b1` 的已评审源身份标识，其汇总摘要为
  `45f4efc0e2a8c7d227d04622ed4dc61ee63430646fd0751dd4e332fd35f5323f`。
- 其存储的源身份标识必须能复现其存储的摘要，还必须与那个独立固定的已评审摘要一致。修改某个身份标识字段后再重新计算存储的摘要，会被拒绝。
- 每次测试运行都会从检出的文件派生当前工具、锁文件、场景运行器、Reference 和 Rust 核心的身份标识。这一实时来源会被报告，但不要求与历史快照相等。
- `sourceRevision` 之外的所有基准证据仍然精确比较：用例、源身份标识、章节摘要与字节边界、诊断、修正和仿真轮次、安全的虚拟意图、总计以及 token 数据。
- 有意进行的新基准测试是一个新的带日期产物。日常的源代码工作绝不会改写已有的历史基准。

针对性的回归测试使用一个真实的临时源树。它：

- 固定预期的树摘要和汇总摘要；
- 证明修改核心身份标识或整个 Reference 的身份标识会改变实时来源，但不会改变基准；
- 拒绝缺失的已声明文件；
- 拒绝对存储的身份标识的篡改，即使其摘要已被重新计算；以及
- 拒绝被修改的基准测量结果。

基准测试查阅过的每个 Reference 章节的确切摘要和字节数，仍然是比较的一部分。
