# 모니터링 계획의 시작 조건

`GhostFlow/monitoring-plan-v1`은 선언된 출력과 제어 로직 사이에서 컴파일러가
확인한 관계를 기록합니다. 선택 필드 `startCondition`은
`scheduled-timed-latch` 관계에 적용합니다.

| 값 | 의미 |
|---|---|
| `schedule-only` | 래치가 일정의 `.due`에서 직접 시작합니다. 컴파일러는 시작 정책이 리터럴 true인 펄스 또는 조건 없는 기존 슬롯을 확인합니다. 제어에는 출력 제약이 없습니다. |
| `conditional` | 추가 시작 조건, 일정 정책 또는 출력 제약이 예정 구간에 영향을 줄 수 있습니다. 서명된 계획에 필드가 없을 때 소비자는 이 값으로 표시합니다. |

장치는 지원되는 일정과 신뢰된 시계가 있을 때 이 구분을 예정 응답에 담을 수
있습니다. 화면은 `schedule-only`를 시각 기반 예정 구간으로 표시합니다. 두
종류 모두 예정입니다. 관측한 전환은 해당 스캔에 연결된 장치의 출력 기록으로
확인합니다. 호스트 실행 권한, 시계 복구와 물리 출력 증거에는 각각의 계약이
적용됩니다.

이식 가능한 패키지의 원문 재검증은 명시된 값을 원문과 대조합니다. 필드가
없는 기존 서명 계획은 원래 메타데이터와 조건부 표시를 유지합니다. 나머지
계획과 산출물 식별자는 재검증합니다. 이 필드를 추가해도 원문과 GFB 바이트는
같습니다.
