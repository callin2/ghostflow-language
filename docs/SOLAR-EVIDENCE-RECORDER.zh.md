# 已接受的 Solar 扫描证据

`runtimes/wasm/solar-evidence-runtime.mjs` 中的 `SolarEvidenceRuntime` 是针对
REF-03-028 的有界参考宿主记录器。它记录运行时已接受的扫描的相关证据。

- 它实例化现有的共享 Solar/config framed Rust WASM 运行时。
- 在创建该负责方之前，它会校验规范源码、字节码、清单（manifest）和追踪元数据。
- 它不改变准入（admission）语义，也不操作硬件。

**输入与身份标识。** 调用方提供：

- 编译后的规范产物；
- WASM 字节；
- 上下文激活；
- 显式的 `runId`。

源文档的 SHA256 是定义修订版。产物的 SHA256 标识可执行字节。记录器不签发安装、
源码或运行的身份标识。

支持的 profile 是现有的 GFB16 共享 Solar 脉冲/config profile。调用方提供有限的
provider 事实和显式的时钟证据。记录器不对天文数据的真实性作任何断言。

**每个被接受的步骤保留什么。** 每个被接受的 `step(frame)` 保留：

- 完整的已提交结果和实际的上下文检查点；
- 源码和产物的哈希；
- 运行、扫描和逻辑时间的身份标识；
- 时钟修订版。

原始的核心追踪行保留其判定。

**准入回执。**

- 真正被接受的 `Due` 回执会为其公开的触发实例（occurrence）身份标识建立准入。
- 之后具有相同身份标识的 provider 行还会额外记录 `AlreadyAdmitted`、源日期、当前
  计划时刻、provider/上下文修订版、可用性与覆盖范围，以及原始准入回执的副本。
- 原始准入元数据与修订后的预测元数据分开保存。
- 启动时错过（boot-missed）的终止键绝不会被呈现为准入。

**`booleanProjection`。** 它描述调度计划当前被接受的扫描。

- 被保留的旧触发实例具有 `occurrenceDue: false`，即使另一个新的触发实例使该次扫描
  的调度计划 Bool 为真。
- 原始的 `coreDecision` 保持可见。仅凭当前可移植的终止键检查点，无法区分已准入的
  触发实例与错过的触发实例。宿主记录器根据实际被接受的回执提供这一分类；它不会
  重新标注核心的判定。

**拒绝、限制与生命周期。**

- 被拒绝的帧不追加任何证据，并保留实际的上下文检查点。
- `observe()` 返回相互独立的副本。
- 该负责方最多允许 256 条回执，JSON 帧限额为 1 MiB。
- 使用后请将其释放（dispose）。
- 不存在物理输出端、持久化写入器或上下文检查点恢复 API。
- 新的激活可以通过重放已记录的帧来复现证据。仅恢复检查点**不会**恢复该宿主的准入
  历史。
- 持久化存储和崩溃恢复仍由外部宿主负责。

**测试。** 专项测试会：

- 比较完整的原生 Rust 与 WASM 结果和检查点；
- 执行真实的准入以及一次 due 为 false 的重新观测；
- 在相同的触发实例身份标识下保留修订后的事实；
- 重放一次新的激活；
- 检查同时存在的新旧触发实例记录；
- 在激活之前拒绝伪造的源码元数据；
- 将缺失、无效和陈旧的证据与已准入的历史区分开来。

这些是软件参考宿主的结果，不能证明 Device 行为或物理执行。
