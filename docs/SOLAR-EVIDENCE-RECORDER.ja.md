# 受け入れられた Solar スキャンの証拠

`runtimes/wasm/solar-evidence-runtime.mjs` の `SolarEvidenceRuntime` は、REF-03-028 のための、範囲を限定した参照ホストのレコーダーです。ランタイムが受け入れたスキャンについての証拠（エビデンス）を記録します。

- 既存の共有 Solar/config のフレーム付き Rust WASM ランタイムをインスタンス化します。
- その所有者を作成する前に、正本ソース、バイトコード、マニフェスト、トレースのメタデータを検証します。
- 受け入れ（アドミッション）のセマンティクスを変更せず、ハードウェアも操作しません。

**入力と同一性。** 呼び出し側は次のものを渡します。

- コンパイル済みの正本の成果物；
- WASM のバイト列；
- コンテキストのアクティブ化；
- 明示的な `runId`。

ソース文書の SHA256 は定義のリビジョンです。成果物の SHA256 は実行可能なバイト列を識別します。レコーダーは、設置、ソース、実行（run）の同一性を発行しません。

サポートされるプロファイルは、既存の GFB16 共有 Solar パルス／config プロファイルです。呼び出し側は、有限のプロバイダの事実と明示的なクロックの証拠を渡します。レコーダーは天文学的な真正性を一切主張しません。

**受け入れられた各ステップが保持するもの。** 受け入れられた各 `step(frame)` は次を保持します。

- 確定した結果の全体と、実際のコンテキストのチェックポイント；
- ソースと成果物のハッシュ；
- 実行、スキャン、論理時間の同一性；
- クロックのリビジョン。

コアの元のトレース行は、その判断を保持します。

**受け入れの受領記録。**

- 実際に受け入れられた `Due` の受領記録は、その公開の発生（オカレンス）の同一性について受け入れを確立します。
- 同じ同一性を持つ後続のプロバイダの行は、さらに `AlreadyAdmitted`、ソース日、現在の計画時刻、プロバイダ／コンテキストのリビジョン、可用性とカバレッジ、そして元の受け入れの受領記録のコピーを記録します。
- 元の受け入れのメタデータと、改訂された予測のメタデータは別々に保持されます。
- 起動時に取りこぼした終端キーが、受け入れとして提示されることは決してありません。

**`booleanProjection`。** これは、スケジュールの現在の受け入れられたスキャンを表します。

- 保持されている古い発生は、別の新しい発生によってそのスキャンのスケジュールの Bool が true になっていても、`occurrenceDue: false` になります。
- 元の `coreDecision` はそのまま見えます。現在のポータブルな終端キーのチェックポイントだけでは、受け入れられた発生と取りこぼした発生を区別できません。ホストのレコーダーが実際の受け入れの受領記録からその分類を提供します。コアの判断のラベルを付け替えることはしません。

**拒否、上限、寿命。**

- 拒否されたフレームは証拠を追加せず、実際のコンテキストのチェックポイントを保持します。
- `observe()` は独立したコピーを返します。
- 所有者が許可するのは最大 256 件の受領記録と、1 MiB の JSON フレームの予算です。
- 使用後は破棄（dispose）してください。
- 物理的な出力先、永続的な書き込み、コンテキストチェックポイントの復元 API はありません。
- 新しいアクティブ化は、記録されたフレームをリプレイすることで証拠を再現できます。チェックポイントを復元するだけでは、このホストの受け入れ履歴は復元**されません**。
- 永続ストレージとクラッシュからの復旧は、引き続き外部ホストの責務です。

**テスト。** 重点テストは次を行います。

- ネイティブの Rust と WASM の結果とチェックポイントの全体を比較する；
- 本物の受け入れと、due が false の再観測を実行する；
- 同じ発生の同一性のもとで、改訂された事実を保持する；
- 新しいアクティブ化をリプレイする；
- 古い発生と新しい発生の記録が同時に存在する場合を確認する；
- アクティブ化の前に、偽造されたソースのメタデータを拒否する；
- 欠落した証拠、不正な証拠、古い（stale）証拠を、受け入れ済みの履歴と区別する。

これらはソフトウェアの参照ホストでの結果であり、Device の動作や物理的な作動の証明ではありません。
