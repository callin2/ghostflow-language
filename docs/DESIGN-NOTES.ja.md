# 言語設計ノート

このページは、GhostFlow の設計の背後にある言語レベルの論拠をまとめたものです。

**選ばれた表面。** GhostFlow プログラムは名前付きの `control` です。次のものを含みます。

- 型付きの宣言
- 明示的な次状態の方程式
- 出力意図の接続

文芸的（literate）ソースは、説明をコードの隣に置きます。実行可能なセマンティクスと
対応付けられた診断は変わりません。コンパイラとポータブルなランタイムは、一緒に
バージョン管理されます。その結果、1 つのプログラムをネイティブと WASM のトレースで
検証し、その後、互換性のある Device ホストで利用できます。

**再現可能な実行。** 4 つの性質が実行を再現可能にします。

- 明示的な状態の境界
- 上限のある式のコスト
- 制約された作用
- 明示的なホスト入力

オプションのセンサや設置のメタデータが、物理的な設備についての仮定を暗黙のうちに
作り出してはなりません。共有ステーションの制約は、明示的なバインディングを持つ実行可能な
ソースまたはプロファイルの契約です。

**さらに詳しく。** 詳細な[言語契約](LANGUAGE.ja.md)、[制御表面](LANGUAGE-SURFACE.ja.md)、
[文芸的ソースの規則](LITERATE.ja.md)、[制約](CONSTRAINTS.ja.md)の各文書は、選ばれた構文と
設計提案を区別しています。[実装の境界](IMPLEMENTATION.ja.md)は、維持されている実行可能な
サブセットを説明しています。

非公開の会話と移行タスクの記録は、この単独のソースエクスポートの外に保管されています。
このページには言語レベルの論拠だけを載せています。
