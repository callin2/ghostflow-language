# GFB5のスケジュールプレリュード

GFB5は、戦略ごとの*プレリュード*にスケジュールのエントリ（現在はSolar）を追加する**内部**バイトコードプロファイルです。プレリュードとは、戦略の遷移と意図が参照できる、ウィンドウとスケジュールのエントリのリストです。現在の状況：

| 部分 | 状況 |
| --- | --- |
| エンコーダ | 実装済み |
| ポータブルなRustの構造検証器 | 実装済み |
| 正準ソースの下げ（lowering） | 未接続 |
| スケジュールの実行 | 未接続 |
| 読み込み | 構造的に有効なモジュールでは成功 |
| アクティベーション、時間計画、ホットスワップ | `schedule activation requires runtime bindings`で拒否 |

## レイアウト

マジックは`GFB1`のままで、リトルエンディアンのフォーマットバージョンは`5`です。

- モジュール、入力、状態、および時間のクロック／ルートのセクションは、既存のレイアウトを維持します。
- スケジュールだけのモジュールは、物理ルートがゼロ個でもかまいません。ウィンドウには引き続き有効なルート参照が必要です。
- フォーマット5のモジュールには、少なくとも1つのスケジュールが含まれていなければなりません。ウィンドウだけのモジュールについては、エンコーダは引き続きフォーマット4を出力します。

各戦略には`u16`のプレリュード数があり、その後にその数だけタグ付きのエントリが続きます。

- タグ`0`には、既存のGFB4のウィンドウ本体が入ります。
- タグ`1`には、次のSolar本体が入ります。

| フィールド | エンコーディングと定義域 |
| --- | --- |
| site | `u32`、正の値 |
| name | 既存のGFB文字列 |
| timezone | 空でない整形式のUTF-8文字列、最大128バイト |
| latitude, longitude | `f64`、有限値。−90..90および−180..180 |
| event | `u8`：0 日の出、1 日の入り |
| offsetMs | `i64`：−86400000..86400000 |
| basis | `u8`：0 pulse |
| clockPolicy | `u8`：0 trusted_only |
| recovery | `u8`：0 baseline |
| fallback | `u8`：0 skip |
| gapMs | `u64`：1..9007199254740991 |
| when | 既存の式のブロブ、Boolの結果、最大4096バイト |

すべての整数はリトルエンディアンです。ポリシーのタグは明示的で、現在、各ポリシーフィールドには定義された値がちょうど1つずつあります。言語の他のポリシーにはさらなる実装が必要です。このプロファイルは、言語がどのポリシーをサポートするかを再定義するものではありません。タイムゾーンが利用可能かどうかはプロバイダのバインディングに属し、構造的なデコードによって確定するものではありません。

**スロットと参照。**

- ウィンドウのスロットとスケジュールのスロットは、出現順に別々に番号付けされます。
- オペコード57は引き続きウィンドウを読み取ります。オペコード58は`[58, u16 scheduleSlot, u8 field]`で、field 0はBool型（`due`）です。
- 各プレリュードの式が参照できるのは、それより前のエントリだけです。遷移と意図はすべてのエントリを参照できます。
- siteとnameは、各戦略内で両方の種類をまたいで一意でなければなりません。
- スカラーの状態とプレリュードのエントリの合計は、戦略ごとに128を超えてはなりません。

## 同一性と境界

バイトコードには、意味的なローカル宣言の同一性が含まれます。文書のハッシュと、外部の文書／リビジョンの同一性は、検証済みの成果物のメタデータに残ります。コメントだけのソース変更が実行可能なバイト列を変えてはなりません。

内部エンコーダの形式は次のとおりです。

```text
(solar-pulse SITE NAME TIMEZONE LAT LON EVENT OFFSET_MS
  pulse trusted_only GAP_MS baseline skip WHEN)
(schedule-read SLOT due)
```

これらの形式は、追加のプロダクトのソース形式ではありません。プロダクトのソースは、引き続き1つの完全な`.ghost.md`文書です。

重点的な証拠は、`tests/gfb5-schedule.test.mjs`、`tests/gfb5-browser.test.mjs`、`tests/gfb5-native.test.mjs`、`crates/ghostflow-core/tests/schedule_module.rs`にあります。

- **検証するもの：** ワイヤフィールド、依存関係の順序、不正な形式の入力、境界、アクティベーションの拒否。
- **確立しないもの：** 予約の受け入れ（アドミッション）、プロバイダの正しさ、スケジュールの実行、永続的な同一性、リソースの使用量計上、リプレイ。
