# 持久化滚动预算解释

**滚动预算**限制某个资源在一个滑动时间窗口内可以处于 ON 状态的时长（例如“任意 60s 内最多 30s 的 ON 时间”）。当某次启动被该预算拒绝时，操作员或工具需要知道*为什么*被拒绝，以及*何时*可以被允许。`explainRolling` 在不改变任何内容的前提下回答这两个问题。

**调用。** `AccountingRuntime.explainRolling({ nowMs, windowMs, limitMs, reserveMs })` 读取一个绑定到已检查源的持久化 `on_time` 账户：

- 经过检查的规范源选定唯一的滚动窗口、限制以及拟议的预留。如果参数与源不一致，调用会被拒绝。
- 复制的不可变绑定会保持该策略，即使调用者试图编辑公开的元数据。

**结果**包括：

- 规范源 SHA 和产物 SHA；
- 账户/目标以及显式的宿主资源 ID；
- 查询时间；
- 已使用的时长（已应用区间的并集）以及未结清的预留时长；
- 限制和拟议的预留；
- `blocked`，以及请求被拒绝时的 `blockReason: 'rolling-budget'`；
- `nextReleaseMs` 和 `ledgerRevision`。

**与准入相同的算术。** Rust 账本计算的已应用区间并集和未结清费用，与真实的 `reserveRolling` 准入所使用的完全相同，因此解释中的预算部分与该准入判定一致。

**完整示例。** 设已应用区间为 [0,20s] 和 [10s,30s]，窗口为 60s，限制为 30s，拟议预留为 5s：

- 在 40s 时，窗口为 [-20s, 40s]。区间的并集为 30s，因此已使用 30s。30s + 5s 超出 30s 的限制，因此请求被阻止。
- 最早可准入的时间是 65s。此时窗口为 [5s, 65s]，已使用 25s，25s + 5s 在限制之内。
- 在 64.999s 时请求仍被拒绝；在 65s 时可以预留。

该查询不会修改账本，也不会授予启动。其他准入失败（例如容量或重复的身份标识）与此预算解释相互独立。

**`nextReleaseMs` 的承诺。** `nextReleaseMs` 假定不会有新的证据到达。其他规则：

- 未结清的预留会一直计费，直到按身份标识被显式结算或取消。经过的时间或 OFF 动画不会释放它们。
- 如果这些费用加上拟议预留已经超出限制，则不承诺任何基于时间的释放。
- 如果预算已经可以准入，`nextReleaseMs` 同样为 null。
- 有界搜索最多执行 64 次并集查询。
- 时间戳在 u64 最大值处饱和，绝不会回绕。
- 早于任何已存储区间结束时间的查询返回 Unknown，因为带有未来日期的证据无法确立一个递减的预测。

**Unknown。** Unknown 返回 null。这包括未初始化或已损坏的状态，以及未被确认的变更（尚未确认已持久化的更改）。

- 只有确切的已持久化修订版才会产生解释证据。
- 修订版编号仅在一个存活的所有者内部有效。恢复之后，它们会从修订版零重新开始。
- 恢复会重放持久化快照和规范源。它不依赖能跨重启保留的修订版计数器。

**宿主职责。** 宿主提供经过验证的已应用证据、稳定的资源绑定，以及可比较且受信任的单调时间线。本 API 不会伪造时钟或绑定修订版，也不会认证物理回执。

**一致性（REF-04-066）。** REF-04-066 测试真实的 WASM 账本拒绝、精确的释放边界、持久化待定期间的 Unknown、快照恢复以及控制激活。另一个从同一快照恢复的上下文账本会产生一个实际已完成的 OFF 输出观测。该观测不会导致滚动拒绝，也不会重置其账本。动画不是用量核算 API 的输入。

**范围。** 这是一个参考性的用量核算投影。它**不是**：

- 前端 cabinet-view 验证；
- 与已编译的 `on_time` 启动/切断的自动集成；
- API 部署；
- 存储介质认证；
- Device 验证。

新增的 WASM 导出需要重新构建 WASM 模块。GFB 和账本快照格式保持不变。
