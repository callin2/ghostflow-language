## Candidate A: translation validation of production output

Define a small proof-checking artifact with four exact inputs: the canonical source bytes and pinned closure, the production parser AST or a normalized typed AST exported from the actual `Lowerer`, the exact `compileSourceSync` result bytes, and the claimed branch/profile. A Node adapter records these values without compiling an alternate program. A Lean checker independently decodes the bytes and checks each supported AST rule against a source semantics and a bytecode semantics. The checker returns a certificate for a named subset or a structured `unsupported`; neither outcome silently asserts full coverage. The production compiler can require this certificate before accepting a supported artifact, while existing behavior for unproved profiles remains explicitly unverified.

The checker must reject a changed byte, changed source, mismatched branch, unsupported opcode, and missing input. If it trusts the production parser AST, its theorem starts **after parsing**. Whole-source correctness also requires an independently checked parser and literate extraction relation. If it trusts a production typed AST, its theorem starts **after type checking**. Such trust boundaries must appear in the certificate. The source map and manifest should be checked against the same exact byte digest, but are separate claims.

The first useful formal component is a Lean proof for one actual GFB scalar profile: an independently decoded, one-strategy Bool/Int/Number expression and simultaneous state-transition fragment. Include literals, input and previous-state reads, candidate-next reads where allowed, comparisons, Boolean short-circuit, conditionals, and arithmetic with the VM's defined fault and overflow behavior. Prove by induction that checking succeeds only when interpreting the source AST yields the same requested output and next state as interpreting the **decoded production bytes** for every well-typed input and prior state in that fragment. Connect the checker to an actual `compileSourceSync` fixture and byte-mutation negative cases. This is substantial because it crosses source AST, core IR, byte encoding, independent decode, and state semantics; its scope remains the named scalar fragment.

Next obligations are closure substitution, each temporal prelude, fault evidence and Result operations, constraints and selection, adaptation/PID, accounting, wrappers, descriptor JSON, trace artifacts, and the actual Rust VM correspondence. Expand the checker only when a profile has both source and bytecode semantics. A Lean proof over hand-written example constructors, or replaying the JS compiler inside the checker, does not establish production compiler correctness.
